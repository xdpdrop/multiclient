## Evidence currently available

The six feature areas have implementations and deterministic coverage: projects/knowledge, web research, versioned artifacts, manual memory, tags/templates, and model comparisons. Shared context, migration, backup and runtime integration are part of their acceptance scope. On October 13, the final-source `npm run check` exited successfully: typecheck, 226 unit/contract tests across 42 files, all native integration/compiled-worker checks, and 41 desktop scenarios passed; the one live Codex scenario was skipped and remains unverified. No automatic retries were used.

The rebuilt Windows unpacked package then passed the same complete desktop suite: 41 passed and one live Codex scenario skipped in 5.9 minutes, without retries. This verifies startup/restart, recovery, workspace workflows, isolated static previews, Mermaid, print-to-PDF and the packaged HTML/PDF worker. Its 10,000-message renderer fixture measured 2,567 ms import/render, 320 ms paging, 253 ms search and 660 ms streaming. The final portable executable passed launch, streaming, persistence, restart and exit checks. It is unsigned, is 150,781,653 bytes, and has SHA-256 `4725211ca80c0a1a5d63745f9062be6ac8ff01f2aa3603ae8733cfb0d156b210`; `release/SHA256SUMS.txt` records the checksum.

Additional scope-specific coverage is maintained in:

- `tests/e2e/instructions.spec.ts`: replacing pending instructions in an empty chat, explicit updated-instruction forks, preserving the original unsent draft and attachments, and remapping selected history. Native-session continuity is covered separately by `tests/unit/coordinator-sources.test.ts`.
- `tests/unit/draft-initialization.test.ts` and `preload-context-contract.test.ts`: fail-closed context loading/retry and actual preload argument serialization, so missing sources cannot silently become a sendable draft.
- `tests/unit/attachments.test.ts`: physical PNG/PDF import followed by deletion of the originals, with exact retained asset bytes and PDF page text. Storage/export/backup tests separately verify the retained references across lifecycle operations.
- `tests/e2e/artifacts.spec.ts`: keyboard-operated Source/Preview tabs opening saved revisions in isolated windows while preserving the working draft. The complete Ask to revise workflow captures a real local API request containing the pinned artifact/revision, verifies that the proposal cannot change the saved head before explicit acceptance, then saves a model-authored revision linked to the completed source message while preserving the original revision.

- Organization's focused run passed all 11 tests against real SQLite/FTS and the template application helper. It includes an older tagged message behind 150 newer untagged matches, additive migration rollback, tag import rollback and revision conflicts.
- Web research evidence combines transport/parser/driver/handler/UI tests, compiled Electron utility-worker HTML/PDF extraction, real SQLite source snapshot round-trips and native JSON desktop import/export. Route registration and argument shapes were inspected across preload, main and utility runtime. An additional standalone compiled-Electron smoke passed on October 13, then passed again against the final Windows package: explicit UI capture of the public RFC 9110 text took 2,511 ms in the packaged run; all 196 captured paragraphs and citation markers reached exactly one keyless local API request; the citation audit and immutable snapshot survived restart without replay, with zero recorded errors. The 60,000-character extraction limit was visibly marked truncated. This used no Brave key or paid inference. The automated suite also covers these boundaries separately. Search account compatibility remains unverified.
- The populated WAL backup/restore and portable conversation/artifact harnesses passed with new libraries, drafts, comparison groups, source/artifact links and assets. Corrupt feature records and unsupported versions were rejected before replacing the active profile.
- The 10,000-message storage and desktop fixtures passed with recorded query, hydration, paging, search and streaming timings. Batched hydration also passed a 1,002-message projection-parity regression using nine queries. Measurements describe the test machine, not a provider-latency or universal performance guarantee.
- No new live provider certification, signed package, human completion study or retention measurement is claimed.

An earlier packaged run passed 40 desktop scenarios and skipped the live case, but its 10,000-message import scenario failed once during concurrent portable compression. The original trace lacked native picker and pointer-event records, so unique historical attribution remains unproven. A matched native-input experiment reproduced a swallowed click in the old initial loading state and showed that the initial loading guard prevents it. Further regressions proved and fixed tab-entry and query/action loading races. Native cancellation/error/retry now has a desktop regression. Broader verification also corrected project-creation fixture readiness and the diagram watchdog's conflation of cold startup with actual rendering. The final complete source check passed 232 unit/contract tests and 42 desktop scenarios; the final package passed all desktop scenarios twice, plus fifteen focused runs and portable restart verification. The [investigation](import-investigation.md) preserves earlier failed checks and causal limits. The performance scenario retains browser traces, picker counts/timestamps, input/disabled transitions and background alerts on import failure; diagnostics redact local paths and do not log import payloads or credentials.
